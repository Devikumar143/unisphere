# Technical Documentation: End-to-End Encryption (E2EE)

UniSphere implements state-of-the-art End-to-End Encryption (E2EE) for direct messaging, ensuring that only the sender and the recipient can read the contents of their messages. The implementation is based on the industry-standard **Signal Protocol**.

## 1. Overview
The E2EE system uses the **Double Ratchet Algorithm** and **X3DH (Extended Triple Diffie-Hellman)** key agreement protocol. This provides two critical security properties:
- **Forward Secrecy**: If a user's current keys are compromised, past messages remain secure.
- **Post-Compromise Healing**: If a user's keys are compromised, they will eventually "heal" as new keys are ratcheted, securing future messages.

## 2. Key Architecture
Each user has a set of several cryptographic keys stored between their device and the server.

### User Device Keys (SecureStore)
Stored locally using `expo-secure-store`:
- **Identity Keypair**: A long-term Curve25519 keypair identifying the user.
- **Registration ID**: A unique random ID for the device.
- **PreKeys**: A large batch of one-time-use Curve25519 keypairs.
- **Signed PreKey**: A Curve25519 keypair signed by the Identity Key.

### Server-Side Public Keys
The UniSphere server acts as a "Key Directory" but never sees private keys:
- `identity_keys` table: Stores public Identity Keys and Registration IDs.
- `prekeys` table: Stores 100+ public One-time PreKeys per user.
- `signed_prekeys` table: Stores the latest public Signed PreKey and its signature.

## 3. The Encryption Workflow

### A. Device Initialization
When a user logs in for the first time or on a new device, the `SignalProtocolService` performs these steps:
1. Generates the **Identity Keypair**, **Registration ID**, and a **Signed PreKey**.
2. Generates a batch of **100 One-time PreKeys**.
3. Uploads all **public** components to the UniSphere backend via `/api/keys`.

### B. Session Establishment (X3DH)
When Sender Alice wants to message Recipient Bob for the first time:
1. Alice's device requests Bob's **PreKey Bundle** from `/api/keys/bundle/bob_id`.
2. The server provides Bob's public Identity Key, Signed PreKey, and *one* of Bob's One-time PreKeys (then deletes it from the server).
3. Alice uses this bundle to initialize a local `Session` for Bob.

### C. Message Encryption & Transmission
1. Sender encrypts the plaintext locally.
2. Ciphertext is sent via Socket.io with `encrypted: true`.
3. Server delivers it to the recipient.
4. Recipient decrypts using local private keys.
